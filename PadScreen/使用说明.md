# PadScreen 使用说明

把 Mac 的虚拟屏幕投到平板上，用平板当副屏。适合终端、聊天和笔记，不是用来看视频的。白色 U03H1 和黑色 K701BC 可以同时各当一块。

白色规格见仓库根目录的 `U03H1-白色.md`，屏幕 1024×600。黑色规格见 `K701BC-黑色.md`，屏幕 800×480。两台都是全志 A20、Android 4.2.2。

## 目录

```
PadScreen/
  Android/    平板端，包名 ai.pad.screen，安装名「副屏」
  Mac/        菜单栏程序，安装到 /Applications/副屏.app
  Windows/    Windows 托盘程序，说明见 Windows/说明.md
  使用说明.md
```

局域网监控是另一个应用，放在仓库根目录的 `monitor/`，和副屏互不影响。

## 日常使用

1. 平板和 Mac 连同一个局域网。平板用 USB 供电即可，Wi-Fi 必须开着。
2. 在平板上打开「副屏」。屏幕上应显示「等待 Mac 连接」。
3. 在 Mac 上打开「副屏」。它没有 Dock 图标，在菜单栏里。
4. 菜单先扫描局域网，列出当前打开了「副屏」的设备，格式是「型号  IP」。扫到几台显示几台。点某一行才会连接，程序不会自动连接。列表不对时点「重新扫描」。
5. 连上的那一行会变成「已连接」。把窗口拖到同名的屏幕上，那台平板就会显示那块屏幕。
6. 单指点按和拖动对应鼠标左键。没有右键，也没有多指手势。
7. 用完在菜单栏选「断开」。退出 Mac 程序后，这块虚拟屏幕会消失，上面的窗口回到主屏幕。

同一时间只服务一台 Mac。平板端没有密码。

## 编译和安装

Android 端需要本机 Android SDK（`~/Library/Android/sdk`，build-tools 34.0.0，platform android-21）。默认装到序列号 `20080411`。旁边如果还插着别的手机，不要省略序列号。

```bash
cd PadScreen/Android
./build.sh
```

只编译、不安装：

```bash
INSTALL=0 ./build.sh
```

装到黑色 K701BC（走网络调试，不要插数据线）：

```bash
ANDROID_SERIAL=192.168.66.147:5555 ./build.sh
```

装别的设备：

```bash
ANDROID_SERIAL=序列号 ./build.sh
```

这条脚本会覆盖安装 `screen.apk`，并重新打开「副屏」。正在投屏时执行它，连接会断，需要在 Mac 上再点一次连接。

Mac 端：

```bash
cd PadScreen/Mac
./build.sh
```

脚本会编译、用「PadScreen Local」证书签名，并安装到 `/Applications/副屏.app`。正在运行的程序会被关掉，虚拟屏幕跟着消失。证书不存在时，`ensure-cert.sh` 会在登录钥匙串里创建它，第一次需要在系统弹窗里确认信任。

## 权限

Mac 端用到两项系统权限，职责不同。

录屏是采集虚拟屏幕所必需的。系统设置里的名称是 **PadScreen**，不是菜单栏上的「副屏」，因为可执行文件名是 PadScreen。允许之后必须退出并重新打开「副屏」，勾上了但进程还是旧的，采集仍会失败。

如果还没允许录屏，系统经常弹出原文类似「用户拒绝了应用程序、窗口、显示器捕捉」的提示。这不代表你点过拒绝，也不代表辅助功能没开。程序这时会打开「录屏与系统录音」。在列表里打开 PadScreen，退出程序再打开。

辅助功能只在第一次把触摸注入鼠标时需要。连接成功本身不应该再弹出辅助功能或系统设置。如果点掉了辅助功能对话框，这一次运行里不会再问，触摸会没有反应，需要自己到「辅助功能」里打开 PadScreen。

本地网络如果被拒绝，菜单会一直停在「正在搜索 U03H1…」，不会出现别的报错。

## 画面和操作

| 项目 | 现在的做法 |
|---|---|
| 虚拟屏幕点大小 | 跟平板面板一致。白色 1024×600，黑色 800×480 |
| 绘制 | 白色是 2048×1200，2 倍后再缩回 1024×600。黑色 800×480 在这台 Mac 上不会生成 2 倍帧缓冲，按 800×480 点对点送出 |
| 帧率 | 最多约 15 帧/秒，来不及就丢帧 |
| 静止画面 | 不发送 |
| 小范围变化 | 只送脏矩形 |
| 整帧 | JPEG 质量 0.86，大约每 20 秒补一帧 |
| 脏矩形 | JPEG 质量 0.92 |
| 平板解码 | ARGB_8888 |
| 发现方式 | Bonjour `_padscreen._tcp.`，服务名是型号（U03H1 或 K701BC），端口 8090 |
| 传输 | 明文 TCP，无密码 |

不要把 2048×1200 直接发给平板。面板只有 1024×600，大图会在这块 A20 上解得很慢。

虚拟屏幕的默认位置在主屏幕外侧。这台 Mac 上曾经被摆在 Studio Display 下方，坐标大约是 (719, -600)。系统会记住新屏幕的排列；如果 Dock 跑到了平板那条边，把 U03H1 的底边放到主屏幕底边之上。

## 调试记录

下面是做到现在为止、已经在这台 U03H1 和这台 Mac 上验证过的问题。

### 卡顿

整屏 JPEG 软解是 A20 的瓶颈。后来改成：采集队列深度 2，上一帧还在发送就跳过编码；32 像素一块比较，没变化不发；小改动只编码脏块；脏块超过 3 块或面积超过一半就改发整帧。

`android/build.sh` 安装后会尝试把 cpu1 打开、调到 performance、频率拉到 1056000。这台平板上的应用没有 root，重启后会回到单核 912 MHz，需要再跑一次安装脚本才会重新加上。

### 每次编译都要重新给录屏权限

临时签名 `codesign --sign -` 每次编译都换 CDHash，系统把「副屏」当成新程序。现在用登录钥匙串里的「PadScreen Local」签名，要求是 `identifier "ai.pad.screen.mac"` 加上这张证书的根。同一张证书重新编译，录屏授权可以留着。

菜单栏显示名是「副屏」，系统设置里要找的是 PadScreen。

### 「用户拒绝了」和辅助功能弹窗

这条拒绝文案来自屏幕录制，不是辅助功能。早期连接时立刻申请辅助功能，所以同意了很多次仍然采不到画面。

后来改成：只有采集接口明确报录屏被拒时，才打开录屏设置。辅助功能只在第一次收到触摸、并且系统还没信任这个程序时问一次。连接成功后不再打开系统设置。

允许录屏之后如果没退出程序，旧进程仍可能被拒。列表很长，PadScreen 不一定在第一屏，搜索框不过滤这一页。

### 平板自动熄屏，连接断开

这台固件忽略 `FLAG_KEEP_SCREEN_ON`。原来的 `screen_off_timeout` 是 60 秒，屏幕一灭，Wi-Fi 跟着睡，TCP 就断了。系统里没有 `wifi_sleep_policy` 这项设置。

现在进入「副屏」会把熄屏超时写成最大值，并拿着亮屏唤醒锁；退出应用时把原来的超时写回去。投屏期间不要从最近任务划掉「副屏」。

### 底部被虚拟按键挡住

导航条高 48 像素，内容一度只有 1024×552。Android 4.2 没有沉浸式粘滞隐藏。只设置布局标志不够，系统会把隐藏标志清掉；在显示回调里同步再藏一次也会被忽略。

现在去掉稳定布局标志，全屏并隐藏导航，显示过程中每 500 毫秒补一次，点完屏幕再藏一次。内容区域是 1024×600。点一下时按键可能闪一下，随后会再藏起来。

### 画面糊

面板像素数就是 1024×600，不能显示更多点。糊的原因是以前按 1 倍绘制，JPEG 质量只有 0.30 / 0.42，解码还是 RGB_565。

2 倍绘制的有效组合是：模式 1024×600，最大像素 2048×1200，打开 HiDPI。这样点大小仍是 1024×600，像素是 2048×1200，缩放是 2。把模式直接设成 2048×1200 并打开 HiDPI，不会得到 2 倍帧缓冲。

旧序列号 `0x03A1` 被系统记住成 1 倍屏，同样的 HiDPI 参数创建出来仍是 1 倍。序列号改成 `0x03B1` 之后才是 2 倍。采集用真实像素，Mac 上用 Lanczos 缩到 1024×600 再编码。平板截图里，菜单栏和 12 像素小字可以辨认。

整帧质量提高后，完整关键帧更重，所以关键帧间隔从 8 秒放宽到 20 秒。

### 安卓图标

启动器格子里的图标大约 55×65 像素。直接放 48 像素图，显示器和平板会糊成一块。现在在 mdpi 资源里放 192 像素图，由图标网格缩进去。图案和 Mac 端相同。应用列表里已经能看到，不再是默认的绿色机器人。

### 重装或重编译之后

Mac 程序一退出，虚拟屏幕就没了，窗口回到主屏幕，需要再拖回 U03H1。Android 端重新安装也会断开当前连接。

本地网络、录屏、辅助功能都是按这个已签名程序记住的。换证书或改成临时签名后，这三项要重新给。
