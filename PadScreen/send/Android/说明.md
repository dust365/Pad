# 安卓发送端

跑在 Android 8 或更新的手机上，去驱动已经打开「副屏」的平板。安装名是「副屏控制」，包名 `ai.pad.screen.send`。两台 A20 是 Android 4.2，装不上这个包。

平板接收端不用换。协议还是原来的：平板先发分辨率和型号，手机再发整帧 JPEG 和脏块，平板把单指触摸送回来。

这不是一块系统级的第二屏幕。普通应用造不出可以随便拖入微信的显示器。小米这类系统也不允许把一个 Activity 启动到虚拟屏上，桌面是直接挂在虚拟屏上的窗口。虚拟屏只属于「副屏控制」自己，平板上只有两页：

- 笔记。正文在手机上用系统输入法写，存在应用私有目录，断开重连还在。两台平板看到的是同一篇。
- 浏览器。网址在手机上输入后点「打开」。平板上点链接、滑动页面。

点按和滑动在平板上。打字在手机上，这样中文输入法可用。

平板同时只接受一个发送端。手机连上某台之后，Mac 要等这台断开才能再连。两台平板可以同时各连一块。

## 编译

在本目录，默认只编译、不安装：

```bash
cd PadScreen/send/Android
./build.sh
```

产物是 `build/send.apk`。需要本机 Android SDK 的 build-tools 34.0.0 和 platform android-34。

装到手机时必须写出那台手机的序列号：

```bash
ANDROID_SERIAL=手机序列号 INSTALL=1 ./build.sh
```

脚本会拒绝这两台平板：`20080411`、`192.168.66.147:5555`、`192.168.66.127:5555`。不要把发送端装到平板上。

## 使用

1. 手机和平板连同一个局域网。平板打开「副屏」。平板上仍会写「等待 Mac 连接」，这是接收端原来的文案。
2. 手机打开「副屏控制」，允许通知。通知用来在切走之后保住投屏。
3. 列表里点一台。连上后平板显示笔记。
4. 要看网页时，在这台连接下面点「浏览器」，输入网址后点「打开」。后退也在手机上。
5. 断开在设备那一行，或在通知里点「断开」。通知里的断开会拆掉全部连接。

白色 U03H1 按 160 dpi 排版，黑色 K701BC 按 120 dpi。画面大约 15 帧，静止不发送，小改动只送脏块。

虚拟屏是否真的出现在平板上，要在手机上连一次才知道。有的系统会把桌面退回手机自己的屏幕，这时控制页会提示虚拟屏没有留在副屏上。
