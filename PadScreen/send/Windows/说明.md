# Windows 版副屏

平板还是原来的「副屏」。这台程序跑在 Windows 上，把一块虚拟屏幕投过去，可以同时连多台。

## Windows 和 Mac 的差别

Mac 的程序自己调用系统私有接口，就能造出一块名叫 U03H1 或 K701BC 的虚拟屏幕。

Windows 没有这个接口。虚拟屏幕必须由**间接显示驱动**提供。它是一个用户态驱动，跑在系统会话里：Windows 把桌面画进这块屏幕，驱动拿到画面。普通程序造不出这块屏幕，所以副屏程序不自己带驱动。没签名的显示驱动系统也不会加载。

程序负责三件事：扫描局域网里打开了「副屏」的平板，把对应虚拟屏幕的画面按原来的协议送过去，再把触摸变回鼠标。单指点按和拖动落在手指的位置，对应鼠标左键。画面里带鼠标光标。协议和 Mac 端相同。

虚拟屏幕不是一直铺在桌面上。没连平板时把它从桌面收起，主屏幕照常能点。连上以后才接到主屏幕右侧外面，断开或退出程序再收回。在普通电脑上，鼠标移出主屏幕右边缘就到这块屏幕。在 Parallels 里窗口只画主屏幕，鼠标如果按整张桌面计算，点击会落到看不见的地方，所以这里把鼠标留在主屏幕；平板上的触摸仍然点虚拟屏幕。要把窗口送到副屏，用 Win+Shift+→。

## 第一次准备

1. 安装 [.NET 8 桌面运行时](https://dotnet.microsoft.com/download/dotnet/8.0)，或者按下面的命令打出一个自带运行时的目录。
2. 运行 `PadScreen.exe`。它没有窗口，图标是一块蓝底白屏，在任务栏右下角。左键或右键都能打开菜单。
3. 点「准备虚拟屏幕」。它会把 `1024×600` 和 `800×480` 写进 `C:\VirtualDisplayDriver\vdd_settings.xml`。系统里还没有虚拟屏幕时，会请求管理员权限并安装 Virtual Display Driver。winget 在 ARM64 上只把驱动文件解出来，安装由旁边的 `install-vdd.ps1` 完成。ARM 版 Windows 不认这块驱动的签名；安全启动关闭时，要先在管理员命令行执行 `bcdedit /set testsigning on` 并重启。失败时会弹出说明。

4. 准备好之后，显示设置里可以先没有新屏幕。新屏幕只在连上平板时出现在主屏幕右侧，断开或退出后收回。连接时若提示没有空闲的虚拟屏幕，再到设备管理器的显示适配器里禁用再启用 Virtual Display Driver。
5. 平板和这台电脑在同一个局域网，平板上打开「副屏」。
6. 菜单里是扫描结果，有几台显示几台。点一行连接。两台可以同时连，各自占一块虚拟屏幕。

日志在 `%LocalAppData%\PadScreen\log.txt`。连不上时先看里面列出的屏幕名称。程序只占用名称里带 Virtual、Indirect、VDD、Idd 的屏幕，不会动正在使用的主屏幕。

## 编译

在本目录：

```powershell
.\build.ps1
```

产物是 `build\PadScreen.exe`。这台 Mac 上编不了这个目标，要在 Windows 上编。
