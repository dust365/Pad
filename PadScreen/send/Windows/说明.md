# Windows 版副屏

平板还是原来的「副屏」。这台程序跑在 Windows 上，把一块虚拟屏幕投过去，可以同时连多台。

## Windows 和 Mac 的差别

Mac 的程序自己调用系统私有接口，就能造出一块名叫 U03H1 或 K701BC 的虚拟屏幕。

Windows 没有这个接口。虚拟屏幕必须由**间接显示驱动**提供。它是一个用户态驱动，跑在系统会话里：Windows 把桌面画进这块屏幕，驱动拿到画面。普通程序造不出这块屏幕，所以副屏程序不自己带驱动。没签名的显示驱动系统也不会加载。

程序负责三件事：扫描局域网里打开了「副屏」的平板，把对应虚拟屏幕的画面按原来的协议送过去，再把触摸变回鼠标。协议和 Mac 端相同。

## 第一次准备

1. 安装 [.NET 8 桌面运行时](https://dotnet.microsoft.com/download/dotnet/8.0)，或者按下面的命令打出一个自带运行时的目录。
2. 运行 `PadScreen.exe`。它没有窗口，在任务栏溢出区里，图标暂时是系统默认的应用程序图标。
3. 点「准备虚拟屏幕」。它会把 `1024×600` 和 `800×480` 写进 `C:\VirtualDisplayDriver\vdd_settings.xml`，并执行：

```powershell
winget install --id=VirtualDrivers.Virtual-Display-Driver -e
```

4. 装完后打开设备管理器，在显示适配器里禁用再启用 Virtual Display Driver。系统的显示设置里应出现两块虚拟屏幕。
5. 平板和这台电脑在同一个局域网，平板上打开「副屏」。
6. 菜单里是扫描结果，有几台显示几台。点一行连接。两台可以同时连，各自占一块虚拟屏幕。

日志在 `%LocalAppData%\PadScreen\log.txt`。连不上时先看里面列出的屏幕名称。程序只占用名称里带 Virtual、Indirect、VDD、Idd 的屏幕，不会动正在使用的主屏幕。

## 编译

在本目录：

```powershell
.\build.ps1
```

产物是 `build\PadScreen.exe`。这台 Mac 上编不了这个目标，要在 Windows 上编。
